# 출력 일관성 & 신뢰도 보장 체계

## 일관성 보장 원칙

| 원칙 | 구현 방법 |
|------|----------|
| 점수 공식 고정 | 코드 메트릭 → 점수 변환 공식 (deterministic) |
| 분류 기준표 | 경력 연수 + 코드 메트릭 + 기여 패턴 조합 |
| 프롬프트 버전 관리 | Langfuse에서 고정, A/B 테스트 후 배포 |
| 출력 스키마 강제 | Pydantic 검증 → 누락/오류 시 재생성 |
| 캐시 활용 | Redis 캐시로 동일 결과 보장 |

## 신뢰도 표시 체계

모든 주요 판단에 3가지 표시:
1. 신뢰도 등급: 🟢 높음 / 🟡 중간 / 🔴 낮음
2. 근거 데이터: "GitHub 12개 레포 + LinkedIn 8년 + 이력서 3장"
3. 데이터 완전성: "분석 가능 데이터 85% 확보"

**산출 기준:**
- 🟢 높음 (≥80%): GitHub + LinkedIn + 이력서 모두 확보
- 🟡 중간 (50-79%): 2개 소스, 일부 분석 실패/데이터 부족
- 🔴 낮음 (<50%): 1개 소스, LLM 추론 의존

## 기준 수립 리서치 프로세스

1. 학술 논문 검색 (ACM, IEEE, arXiv 우선)
2. 산업 표준 참조 (Google Levels, SFIA, Dreyfus)
3. 기준 문서화 → `docs/scoring/`
4. A/B 검증: 테스트 Job으로 비교
