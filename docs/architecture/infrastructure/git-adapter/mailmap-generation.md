# Mailmap Generation

> `infrastructure/git/mailmap_writer.py` 구현 설계.
> Domain Layer(`mailmap_builder`)가 생성한 `MailmapEntry` 목록을 `.mailmap` 파일로 직렬화하여
> clone 디렉토리에 쓴다. `git blame`은 이 파일을 자동으로 적용한다.

## .mailmap 파일 형식

Git은 레포 루트의 `.mailmap` 파일을 blame/log 시 자동 적용한다.

```
# 형식: <정규 이름> <정규 이메일> [<별칭 이름> [<별칭 이메일>]]

# 케이스 1: 이메일만 다를 때 (이름 동일)
Gildong Hong <gildong@personal.com> <gildong@company.com>

# 케이스 2: 이름과 이메일 모두 다를 때
Gildong Hong <gildong@personal.com> GD Hong <gd@old-company.com>

# 케이스 3: noreply 이메일 매핑 (GitHub Web 커밋)
Gildong Hong <gildong@personal.com> <12345678+gildong@users.noreply.github.com>
```

## 구현

```python
# infrastructure/git/mailmap_writer.py
from pathlib import Path
from domain.identity.models import MailmapEntry

class MailmapWriter:
    """domain/identity/mailmap_builder의 결과를 .mailmap 파일로 직렬화"""

    MAILMAP_FILENAME = ".mailmap"

    async def write(
        self,
        clone_dir: Path,
        entries: list[MailmapEntry],
    ) -> Path:
        """clone_dir에 .mailmap 파일을 생성하고 경로를 반환.

        Args:
            clone_dir: shallow clone된 레포 루트
            entries: domain/identity/mailmap_builder가 생성한 엔트리 목록

        Returns:
            Path: 작성된 .mailmap 파일 경로
        """
        mailmap_path = clone_dir / self.MAILMAP_FILENAME
        content = self._serialize(entries)
        mailmap_path.write_text(content, encoding="utf-8")
        return mailmap_path

    def _serialize(self, entries: list[MailmapEntry]) -> str:
        """MailmapEntry 목록 → .mailmap 텍스트 직렬화"""
        lines = [
            "# Auto-generated by Jittda Sniper v5.0",
            "# DO NOT EDIT — regenerated on each analysis run",
            "",
        ]

        # confidence 순 정렬: high → medium → low
        order = {"high": 0, "medium": 1, "low": 2}
        sorted_entries = sorted(entries, key=lambda e: order.get(e.confidence, 3))

        for entry in sorted_entries:
            comment = f"# confidence: {entry.confidence}"
            mailmap_line = self._format_entry(entry)
            lines.append(comment)
            lines.append(mailmap_line)

        return "\n".join(lines) + "\n"

    def _format_entry(self, entry: MailmapEntry) -> str:
        """단일 MailmapEntry → .mailmap 줄 형식화"""
        canonical = f"{entry.canonical} <{entry.canonical_email}>"
        alias_parts = []

        if entry.alias_name and entry.alias_name != entry.canonical:
            alias_parts.append(entry.alias_name)
        if entry.alias_email:
            alias_parts.append(f"<{entry.alias_email}>")

        if alias_parts:
            return f"{canonical} {' '.join(alias_parts)}"
        else:
            # alias가 없으면 canonical만 기록 (정규화용)
            return canonical

    async def read_existing(self, clone_dir: Path) -> list[str]:
        """레포에 이미 존재하는 .mailmap 내용 읽기 (병합 시 참조용)"""
        mailmap_path = clone_dir / self.MAILMAP_FILENAME
        if not mailmap_path.exists():
            return []
        return mailmap_path.read_text(encoding="utf-8").splitlines()
```

## Domain과의 책임 분리

```
[Domain]  mailmap_builder.build_dynamic_mailmap()
          - git 히스토리 이메일 클러스터링
          - Levenshtein similarity 계산
          - noreply 패턴 매칭
          - confidence 레벨 결정
          → list[MailmapEntry] 반환

[Infrastructure]  MailmapWriter.write()
          - .mailmap 파일 포맷 직렬화
          - 파일시스템 I/O
          - confidence 기반 정렬
```

Domain 모델 `MailmapEntry`를 infrastructure가 소비하지만 **import 방향은 infrastructure → domain이 아닌** domain 모델을 매개변수로 전달받는 방식이다. DDD 의존성 규칙을 위반하지 않는다.

## Git Blame과의 연동

`.mailmap`은 git이 기본으로 레포 루트에서 자동 로딩한다. 별도 플래그가 필요 없다.

```bash
# .mailmap 적용 확인
git -C <clone_dir> log --format="%an <%ae>" | sort -u

# 적용 전/후 비교
git -C <clone_dir> blame -w -M -C -C -- src/main.py | head -20
```

.mailmap이 없으면 `git blame`은 커밋에 기록된 raw 이름/이메일을 그대로 사용한다. 동일인이 여러 이메일로 커밋하면 blame 결과에서 다른 사람으로 집계된다.

## identity_resolver_node 호출 순서

```python
# application/nodes/identity_resolver.py
async def identity_resolver_node(state: ForensicState) -> dict:
    # 1. infrastructure: git 저자 목록 추출
    authors = await git_author_extractor.extract(state["clone_dir"])

    # 2. infrastructure: GitHub Node ID 조회
    node_id = await github_client.get_user_node_id(state["candidate_username"])

    # 3. domain: mailmap 생성 (순수 비즈니스 로직)
    entries = mailmap_builder.build_dynamic_mailmap(
        authors, state["github_profile"], node_id
    )

    # 4. infrastructure: .mailmap 파일 쓰기 ← MailmapWriter
    await mailmap_writer.write(state["clone_dir"], entries)

    # 5. infrastructure: git blame -w -M -C -C 실행
    blame_lines = await blame_runner.run_git_blame(
        state["clone_dir"], state["target_files"]
    )

    # 6. domain: blame 필터링
    identity_cluster = IdentityCluster.from_entries(entries, node_id)
    filtered = blame_filter.filter_by_cluster(blame_lines, identity_cluster)

    return {
        "blame_attributions_ref": await repo.save_blame(filtered, state["job_id"]),
        "identity_cluster": identity_cluster.model_dump(),
    }
```

## 기존 .mailmap 병합 정책

레포에 이미 `.mailmap`이 존재하는 경우:

1. 기존 내용을 `read_existing()`으로 읽는다.
2. Jittda가 생성한 엔트리를 추가로 병합한다.
3. 중복 엔트리는 canonical_email 기준으로 deduplicate.

```python
async def write_with_merge(
    self, clone_dir: Path, entries: list[MailmapEntry]
) -> Path:
    existing_lines = await self.read_existing(clone_dir)
    new_content = self._serialize(entries)
    merged = "\n".join(existing_lines) + "\n\n# === Jittda additions ===\n" + new_content
    mailmap_path = clone_dir / self.MAILMAP_FILENAME
    mailmap_path.write_text(merged, encoding="utf-8")
    return mailmap_path
```
