# 01. System Overview

> Vantict Sniper v4.0 - AI Technical Interview Script Generator

---

## 1. 시스템 목적

### 1.1 해결하는 문제
- 비개발자 면접관이 기술 면접을 진행할 때의 어려움
- 후보자의 실제 코드 경험을 검증하기 어려움
- 면접 질문이 일반적이고 실제 경험과 연결되지 않음
- 기술 용어에 대한 이해 부족

### 1.2 솔루션
후보자의 **실제 코드**와 **경력**을 분석하여:
- 반박 불가능한 맞춤형 질문 생성
- 비개발자도 읽을 수 있는 면접 스크립트 제공
- 예상 답변과 평가 기준 제시
- 기술 용어를 쉽게 설명

## 2. 핵심 기능

### 2.1 입력 (Input)
| 입력 타입 | 형식 | 필수 여부 | 설명 |
|----------|------|----------|------|
| 이력서 | PDF | 선택 | 경력, 학력, 기술 스택 (LinkedIn URL, GitHub URL 자동 추출) |
| LinkedIn URL | URL | 선택 | Bright Data API로 프로필 수집 (이력서 대체 가능) |
| 포트폴리오 | DOCX/PDF | 선택 | 프로젝트 상세 설명 (GitHub URL 자동 추출) |
| 커버레터 | PDF/DOCX | 선택 | 자기소개서/커버레터 (GitHub URL 자동 추출) |
| GitHub URL | URL 목록 | 선택 | 실제 코드 분석 대상 (Public만, 다른 입력에서 자동 추출 가능) |
| 채용공고 (JD) | 텍스트 | 필수 | 직무 요구사항 |
| 경험 레벨 | 선택 | 필수 | 신입/주니어/미들/시니어/CTO/VP |
| 출력 언어 | 선택 | 필수 | 12개 언어 지원 |

> **Smart Input Extraction**: 유저가 모든 필드를 직접 입력할 필요 없음.
> 시스템이 제공된 입력(이력서, 포트폴리오, 커버레터, LinkedIn)에서 GitHub URL, LinkedIn URL 등을
> 자동으로 교차 추출하여 빈 필드를 채운 뒤 Planning을 시작합니다.

### 2.2 출력 (Output)
```
Interview Script
├── 후보자 요약
│   ├── 핵심 기술 스택
│   ├── 경력 요약
│   └── JD 매칭 점수
│
├── 질문 25개 (각 질문별)
│   ├── 메인 질문 (주 언어, 다국어는 on-demand)
│   ├── 대체 표현 2-3개
│   ├── 관련 코드 스니펫
│   ├── 예상 답변 스크립트
│   ├── 평가 시나리오 (우수/양호/미흡)
│   ├── 꼬리질문 2-3개
│   └── 용어 설명 (동의어 포함)
│
└── 면접관 가이드
    ├── 전체 소요 시간
    ├── 질문 순서 가이드
    └── 주의사항
```

### 3.2 Component Responsibilities

| 컴포넌트 | 역할 | 상세 |
|---------|------|------|
| **Input Enricher** | 입력 보강 | 모든 입력에서 URL/프로필 교차 추출, Bright Data LinkedIn 수집, 필드 자동 채움 |
| **Planner** | 실행 계획 | enriched input 기반 워크로드 추정, 실행 순서 결정 |
| **Document Manager** | 문서 분석 | PDF/DOCX 파싱, 프로필 구축 |
| **Code Manager** | 코드 분석 | PyGithub(레포선별) → PyDriller(커밋추출) → AST(구조분석) → LLM(의미분석) 4-Phase |
| **JD Manager** | JD 분석 | 요구사항 추출, 스킬 매칭 |
| **Question Generator** | 질문 생성 | 토픽 선정, 질문 작성, 품질 검토 |
| **Supervisor** | 최종 검증 | Hallucination 검증, 포맷 검증, 출력 |

## 5. 핵심 설계 원칙

### 5.1 Local-First, Cloud-Ready
```
원칙: 로컬에서 100% 동작하고, 환경 변수만 바꾸면 클라우드로 전환
```
- Docker Compose로 전체 환경 로컬 실행
- LocalStack으로 AWS 서비스 에뮬레이션
- Temporal의 동일 코드 실행 특성 활용

### 5.2 Job-Based Isolation
```
원칙: 모든 작업은 UUID로 식별되고, 데이터가 완전히 격리됨
```
- 각 면접 생성 요청 = 하나의 Job
- Job별로 DB 레코드, 벡터 네임스페이스, S3 경로 분리
- 동시에 여러 Job 병렬 실행 가능

### 5.3 Evidence-Based Questions
```
원칙: 모든 질문은 실제 코드 증거에 기반해야 함 (Hallucination 방지)
```
- 질문 생성 시 반드시 코드 참조 포함
- 예상 답변도 실제 구현 기반
- Supervisor가 최종 검증

### 5.4 Non-Developer Friendly
```
원칙: 모든 출력은 비개발자 면접관이 이해할 수 있어야 함
```
- 기술 용어에 동의어 및 설명 추가
- 예상 답변을 자연스러운 대화체로 작성
- 평가 시나리오를 구체적으로 제시

## 7. 제약 사항 및 가정

### 7.1 MVP 범위 제약
- **언어**: JD 기반 다국어 분석 (MVP: Python `ast` + JS/TS `tree-sitter`)
- **코드 분석**: Public GitHub 레포지토리만 (Private 미지원)
- **LinkedIn**: Bright Data API 사용 (유료, $0.01/profile)
- **문서**: PDF, DOCX 형식만 지원
- **동시 작업**: 단일 서버 기준 5개 Job 동시 처리

### 7.2 기술적 가정
- LLM API 가용성 (OpenAI/Anthropic)
- GitHub API Rate Limit 고려 (인증 토큰 사용)
- PostgreSQL pgvector 확장 사용 가능

### 7.3 품질 기준
- 질문당 생성 시간: 30초 이내
- 전체 처리 시간: 8분 이내 (25개 질문)
- Hallucination 허용률: 0% (검증 실패 시 재생성)
