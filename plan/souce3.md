네, 정확합니다. **4개의 주지표(Main Indicators)**는 단순히 하나의 데이터로 결정되는 것이 아니라, **다양한 세부 지표(Sub-metrics)**들을 정밀하게 측정하고, 이를 **가중 합산 모델(WSM, Weighted Sum Model)**로 계산하여 도출된 결과값입니다.

소스 자료에 따르면, 이 과정은 **'결정론적(Deterministic)'** 방법론을 따릅니다. 즉, 동일한 코드라면 언제 분석하더라도 동일한 세부 지표와 최종 점수가 나와야 합니다.

각 주지표가 어떤 **세부 지표(Raw Data & Metrics)**를 바탕으로 계산되는지 계층 구조로 정리해 드립니다.

---

### 1. 논리력 점수 (Logic Score)
**"얼마나 효율적이고 튼튼한 코드를 짜는가?"**

이 점수는 코드의 **복잡도**와 **인지적 난이도**를 수학적으로 계산하여 산출합니다.

*   **세부 지표 1: 할스테드 난이도 (Halstead Difficulty)**
    *   **측정법:** 연산자(Operator)와 피연산자(Operand)의 고유 개수와 총사용 횟수를 대입하여 계산 ($D = \frac{\eta_1}{2} \times \frac{N_2}{\eta_2}$).
    *   **의미:** 구현된 기능의 부피(Volume) 대비 코드를 이해하고 작성하는 데 필요한 정신적 노력을 수치화합니다. 기능은 많은데 난이도가 낮다면 효율적인 코드입니다.
*   **세부 지표 2: 맥케이브 순환 복잡도 (Cyclomatic Complexity)**
    *   **측정법:** 제어 흐름 그래프에서 독립적인 경로의 수 측정 ($M = E - N + 2P$).
    *   **의미:** `if`, `for`, `while` 등의 분기 처리가 얼마나 얽혀있는지 봅니다. 수치가 낮을수록 모듈화가 잘 된 것입니다.

### 2. 전문성 점수 (Mastery Score)
**"해당 기술 스택을 얼마나 깊이 있게 다루는가?"**

단순 텍스트 검색이 아닌 **AST(추상 구문 트리)** 분석을 통해, 사용한 문법의 수준을 측정합니다.

*   **세부 지표 1: API 활용 깊이 (API Depth)**
    *   **측정법:** 프레임워크 내 함수/클래스 호출을 분석하여 가중치 부여.
    *   **예시:** Spring Boot에서 단순 `CRUD`만 구현하면 기본 점수, `AOP`, `Transaction` 관리, `Security` 설정을 사용하면 가산점 부여.
*   **세부 지표 2: 아키텍처 준수율 (Design Pattern Usage)**
    *   **측정법:** 소스 코드 구조에서 '전략 패턴', '팩토리 패턴' 등의 구조적 특징(Signature)을 탐지.
    *   **의미:** 기능 구현을 넘어 유지보수를 고려한 설계를 했는지 판단합니다.

### 3. 안정성 점수 (Stability Score)
**"작업 방식이 안정적인가, 아니면 시행착오가 많은가?"**

Git 메타데이터를 분석하여 개발자의 **작업 습관**과 **코드의 건전성**을 평가합니다.

*   **세부 지표 1: 리워크 비율 (Rework Rate / Code Churn)**
    *   **측정법:** 특정 기간 내에 생성된 코드 대비, 곧바로 수정되거나 삭제된 코드의 비율.
    *   **의미:** 이 비율이 높으면 기획/설계 없이 코드를 막 짜서 자주 갈아엎었다는 뜻입니다.
*   **세부 지표 2: 기술 부채 상환 시간 (Technical Debt Ratio)**
    *   **측정법:** SonarQube API 등을 통해 코드 스멜, 중복, 취약점을 수정하는 데 걸리는 예상 시간 산출.
    *   **의미:** 품질보다 속도에만 치중했는지를 보여주는 역지표(Negative Indicator)입니다.

### 4. 진정성 지수 (Authenticity Index)
**"이 코드는 AI나 남의 것이 아닌, 본인의 것인가?"**

가장 중요한 신뢰 지표로, **포렌식 기법**을 사용하여 허수를 제거합니다.

*   **세부 지표 1: 타이핑 속도 위반 (Typing Speed Violation)**
    *   **측정법:** 커밋 시간과 변경된 코드 양(LoC)을 분석하여 분당 속도(WPM) 계산 ($Speed = \frac{\Delta LoC}{\Delta Time}$).
    *   **의미:** 인간 한계(40-80 WPM)를 초과하는 구간은 AI 생성 코드나 복사/붙여넣기로 간주하여 점수에서 배제합니다.
*   **세부 지표 2: 순수 기여도 (Pure Contribution)**
    *   **측정법:** `git-filter-repo`와 `LSH 알고리즘`을 사용해 보일러플레이트, 오픈소스 포크, 라이브러리 코드를 제외한 실제 작성 코드 비율 계산.
    *   **의미:** 겉으로 보이는 코드 양에서 거품을 걷어낸 '진짜 실력'의 비율입니다.

---

### [결론] 최종 점수는 어떻게 나오는가?

위의 세부 지표들을 **가중 합산 모델(WSM)**에 대입하여 최종 점수를 산출합니다.

$$ \text{최종 점수} = (W_1 \times \text{논리력}) + (W_2 \times \text{전문성}) + (W_3 \times \text{안정성}) + (W_4 \times \text{진정성}) $$

*   **가중치($W$) 예시:**
    *   논리적 구현 능력: **30%** (기본기)
    *   프레임워크 숙련도: **30%** (즉시 전력감 여부)
    *   코드 안정성: **20%** (유지보수성)
    *   행동 및 규율(진정성): **20%** (신뢰도)

따라서 채용 담당자에게 보여주는 **4개의 주지표**는 단순히 직관에 의한 평가가 아니라, **소스 코드와 Git 히스토리라는 'Fact'를 미분하여 얻어낸 세부 지표들의 적분값**이라고 설명할 수 있습니다.
