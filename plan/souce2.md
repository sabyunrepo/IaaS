채용 담당자(비기술자 CEO 포함)가 직관적으로 이해할 수 있으면서도, **기술적으로 '결정론적(Deterministic)'이고 '신뢰할 수 있는(Trustworthy)' 수치**만을 엄선하여 정리해 드립니다.

소스 코드 분석을 통해 우리가 뽑아낼 수 있는 데이터는 크게 **1. 코드 품질(기본기), 2. 기술 숙련도(전문성), 3. 작업 스타일(생산성), 4. 진위 여부(검증)**의 4가지 카테고리로 나뉩니다.

---

### 1. 코드 품질 및 기본기 (Code Quality & Fundamentals)
**"이 사람이 짠 코드는 얼마나 튼튼하고 유지보수하기 쉬운가?"**

*   **맥케이브 순환 복잡도 (Cyclomatic Complexity)**
    *   **정의:** 코드 내의 분기(if, for, while)가 얼마나 얽혀있는지를 나타내는 수치입니다.
    *   **채용 의미:** **수치가 낮을수록 좋습니다.** 복잡한 로직을 작은 함수로 잘 쪼개서 관리한다는 뜻이며, 버그가 발생할 확률이 낮음을 의미합니다. 반대로 수치가 높으면 유지보수가 불가능한 '스파게티 코드'를 짤 확률이 높습니다.
*   **할스테드 난이도 (Halstead Difficulty)**
    *   **정의:** 코드를 작성할 때 투입된 인지적 노력을 수치화한 것입니다.
    *   **채용 의미:** **"부피(Volume) 대비 난이도가 적절한가"**를 봅니다. 숙련된 개발자는 기능을 많이 구현(높은 부피)하면서도, 언어의 기능을 잘 활용하여 난이도를 낮게 유지하는 경향이 있습니다.
*   **기술 부채 상환 시간 (Technical Debt Ratio)**
    *   **정의:** 현재 코드의 문제점(코드 스멜, 중복, 취약점)을 수정하는 데 걸리는 예상 시간입니다.
    *   **채용 의미:** **"입사 후 똥 치우는 데 며칠이 걸릴까?"**를 보여줍니다. 이 수치가 높으면, 기능 개발보다 버그 수정에 시간을 더 쏟을 지원자입니다.

### 2. 기술 숙련도 및 깊이 (Stack Proficiency & Depth)
**"이력서에 적힌 'React/Java 가능'이 진짜인가, 겉핥기인가?"**

*   **API 활용 깊이 점수 (API Depth Score)**
    *   **정의:** 단순히 기초 함수(`print`, `console.log`)만 쓰는지, 프레임워크의 고급 기능(예: Spring의 `@PreAuthorize`, React의 `useMemo`)을 쓰는지 AST(구문 트리)로 분석한 점수입니다.
    *   **채용 의미:** 지원자의 **진짜 기술 레벨(Junior vs Senior)**을 가릅니다. 단순 구현을 넘어 보안, 최적화, 비동기 처리를 할 줄 아는지 증명합니다.
*   **아키텍처 준수율 (SOLID/Pattern Score)**
    *   **정의:** 디자인 패턴(Strategy, Factory 등)과 객체지향 원칙(SOLID)을 얼마나 코드에 적용했는지 수치화한 것입니다.
    *   **채용 의미:** **"설계 능력이 있는가?"**를 보여줍니다. 대규모 트래픽이나 복잡한 시스템을 감당할 수 있는 아키텍트급 역량을 판단하는 핵심 지표입니다.

### 3. 작업 스타일 및 생산성 (Work Style & Productivity)
**"이 사람은 꾸준히 일하는가, 아니면 몰아서 대충 하는가?"**

*   **리워크 비율 (Rework Rate / Code Churn)**
    *   **정의:** 작성한 코드 대비 나중에 수정되거나 삭제된 코드의 비율입니다.
    *   **채용 의미:** **"한 번에 제대로 짜는가?"**를 보여줍니다. 이 비율이 지나치게 높으면 시행착오를 많이 겪거나 설계를 자주 뒤엎는다는 뜻으로, 업무 효율이 떨어짐을 시사합니다.
*   **램프업 속도 (Ramp-up Speed)**
    *   **정의:** 프로젝트에 투입된 후 '첫 번째 의미 있는 기여'를 하기까지 걸린 시간입니다.
    *   **채용 의미:** **"채용 후 밥값 하기까지 얼마나 걸릴까?"**를 예측합니다. 새로운 기술이나 환경에 얼마나 빨리 적응하는지 보여주는 지표입니다.

### 4. 진위 여부 및 윤리성 (Authenticity & Ethics)
**"이 코드를 본인이 짠 게 맞는가?" (가장 중요한 신뢰 지표)**

*   **인간 타이핑 속도 준수 여부 (Human Typing Speed Limit)**
    *   **정의:** 커밋된 코드 양과 시간을 분석하여 분당 타이핑 속도(WPM)를 계산합니다. 인간 한계(40-80 WPM)를 초과하면 AI 생성 코드나 복사/붙여넣기로 간주합니다.
    *   **채용 의미:** **"AI 뺑끼(?)인가, 실력인가?"**를 걸러냅니다. ChatGPT로 생성한 코드를 그대로 복사해 넣는 지원자를 식별하여 거를 수 있습니다.
*   **순수 기여도 (Pure Contribution)**
    *   **정의:** 프레임워크가 자동 생성한 코드(Boilerplate), 외부 라이브러리, 포크(Fork)한 코드를 모두 제거하고 남은 순수 로직의 양입니다.
    *   **채용 의미:** **"거품을 뺀 진짜 코딩 양"**입니다. 이력서에 "10만 라인 작성"이라고 써 있어도, 순수 기여도가 1%라면 채용해서는 안 됩니다.

### [요약] 채용 담당자에게 보여줄 최종 대시보드 예시

우리는 위 데이터들을 종합하여 다음과 같은 **'신뢰할 수 있는 4가지 핵심 지표'**로 시각화해 줄 수 있습니다. (가중 합산 모델 적용)

1.  **논리력 점수 (Logic Score):** 복잡도와 난이도 최적화 능력 (상위 10% 등급 표기)
2.  **전문성 점수 (Mastery Score):** 기술 스택 깊이 및 아키텍처 설계 능력
3.  **안정성 점수 (Stability Score):** 기술 부채가 없고 리워크가 적은 정도
4.  **진정성 지수 (Authenticity Index):** AI/복붙 없이 직접 작성한 순수 코드 비율 (예: 98% Real Human Code)

이 수치들은 단순한 텍스트 검색이 아니라, **AST(구문 트리) 분석과 Git 히스토리 포렌식**을 통해 추출되므로, "면접 때는 말 잘하던데 코드는 엉망이더라"는 리스크를 **결정론적(수학적)으로 제거**해 줄 수 있습니다.
