제시해주신 소스(기획 및 기술 분석 보고서)를 바탕으로, **'짓다(Jitta)'** 프로젝트의 핵심 목표인 **정확도(Accuracy)**, **확실한 수치화(Quantification)**, **빠른 분석(Speed)**을 달성하기 위한 최종 기술 설계 및 실행 플랜을 제안합니다.

요청하신 **에이전트 병렬화**와 **최신 라이브러리**를 중심으로 아키텍처를 구성하였습니다.

# [프로젝트 Jitta] 최종 기술 아키텍처 및 구현 설계

## 1. 시스템 설계 원칙 (Design Principles)
본 설계는 소스 자료에서 제시된 **'순수 코드 기여분(Pure Code Contribution)'** 추출과 **'결정론적 숙련도 측정(Deterministic Measurement)'**을 핵심 가치로 삼습니다.

1.  **Noise-Free:** 포크(Fork), 라이브러리, 자동 생성(AI/Boilerplate) 코드를 완벽히 제거.
2.  **Semantic Analysis:** 텍스트 기반이 아닌 AST(추상 구문 트리) 기반의 논리적 분석 수행.
3.  **Parallel Execution:** 데이터 수집, 정제, 분석, LLM 추론을 비동기 에이전트로 병렬 처리하여 속도 최적화.

---

## 2. 핵심 라이브러리 및 프레임워크 선정 (Tech Stack)

분석의 정확도와 속도를 위해 소스 코드 내에서 검증된 도구와 이를 보완할 최신 프레임워크를 매칭했습니다.

| 영역 | 기능 정의 | 추천 라이브러리/프레임워크 | 선정 근거 및 소스 |
| :--- | :--- | :--- | :--- |
| **데이터 수집** | GitHub API 최적화 | **GraphQL (Apollo Client / GQL)** | REST API 대비 호출 횟수 최소화 및 정밀 쿼리 가능. |
| **Git 포렌식** | 히스토리 마이닝 | **PyDriller** | 커밋 순회, 저자 식별, Diff 추출을 위한 파이썬 프레임워크 표준. |
| **구문 분석** | 시맨틱 파싱 & Diff | **Tree-sitter** | 증분 파싱을 통해 논리적 변화(Semantic Diff)만 추출하고 포맷팅 노이즈 제거. |
| **복잡도 측정** | 정량적 지표 산출 | **Radon (Python) / Lizard** | 순환 복잡도(McCabe) 및 Halstead 지표 계산을 위한 경량화 도구. |
| **정적 분석** | 코드 품질/부채 | **SonarQube API** | 기술 부채, 코드 스멜, 보안 취약점의 정량적 수치 확보. |
| **중복 제거** | 오픈소스 표절 탐지 | **Datasketch (LSH 알고리즘)** | 대규모 데이터셋(FOSS)과 비교하여 유사도(MinHash/LSH) 기반 필터링. |
| **병렬 처리** | **에이전트 오케스트레이션** | **LangGraph / Ray** | 분석 단계별 에이전트(수집/분석/평가)를 병렬로 실행하고 상태를 관리하기 위함. |

## 3. 에이전트 병렬화 파이프라인 (Agent Workflow)

빠른 분석을 위해 단일 프로세스가 아닌, **3개의 전문 에이전트가 병렬로 작동**하며 결과를 중앙 'Synthesizer(종합 분석기)'로 전송하는 구조를 제안합니다.

### Step 1. 수집 및 전처리 에이전트 (Collector Agent)
*   **역할:** 데이터 획득 및 노이즈 1차 필터링.
*   **핵심 로직:**
    *   **GraphQL 쿼리:** `isFork: false` 조건으로 유저의 오가니제이션 및 개인 레포지토리 리스트 확보.
    *   **Git-filter-repo:** 클론 후 바이너리 파일, `node_modules` 등 불필요한 대용량 파일 및 보일러플레이트 디렉토리 영구 제거.
    *   **LSH 중복 탐지:** 오픈소스 인덱스와 대조하여 외부 유입 코드 제외.

### Step 2. 포렌식 분석 에이전트 (Forensic Agent)
*   **역할:** '누가' '무엇을' '어떻게' 짰는지 검증 (Source 9-17 기반).
*   **병렬 태스크:**
    *   **순수 기여 추출:** `git blame -w -M -C` 옵션을 적용하여 공백 무시, 이동된 코드 추적, 복사된 코드 식별.
    *   **AI 생성 탐지(Vibector):** 커밋 시간과 코드량(LoC)을 분석, 분당 타이핑 속도가 인간 한계(40-80 WPM)를 초과하는 구간 마킹 및 배제.
    *   **스타일로메트리(Stylometry):** SCAA 기술을 활용, 코드 스타일 지문을 분석하여 계정 공유나 대리 코딩 의심 사례 탐지.

### Step 3. 역량 측정 에이전트 (Metric Agent)
*   **역할:** 코드의 질적 수준을 수치화 (Source 18-27 기반).
*   **병렬 태스크:**
    *   **복잡도 계산:** AST 파싱을 통해 **Halstead Metrics(부피, 난이도)**와 **McCabe 순환 복잡도** 산출.
    *   **기술 스택 프로파일링:** 단순 import가 아닌, AST 노드 내 API 호출 깊이(예: React `useMemo`, Spring `AOP`)를 분석하여 숙련도 점수화.
    *   **아키텍처 분석:** 디자인 패턴 사용 여부 및 SOLID 원칙 준수 여부(클래스 응집도 등) 스캔.

## 4. 최종 데이터 종합 및 질문 생성 (Synthesizer & LLM)

각 에이전트가 산출한 정형 데이터(JSON)를 바탕으로 LLM이 최종 인사이트를 도출합니다.

1.  **가중 합산 모델(WSM) 적용:**
    *   논리적 구현 능력(30%) + 프레임워크 숙련도(30%) + 코드 안정성(20%) + 행동 규율(20%)로 최종 점수 산출.
2.  **질문 생성 (Interview Gen):**
    *   단순한 "이 기술 아시나요?"가 아닌, **"왜 이 구간에서 순환 복잡도가 높은 로직을 사용했나요?"** 혹은 **"이곳의 예외 처리가 누락된 이유는 무엇인가요?"**와 같이 분석된 취약점을 타격하는 질문 생성.
    *   비기술자 CEO를 위한 '예상 모범 답안' 및 '답변 평가 가이드' 함께 생성.

## 5. 단계별 구현 로드맵 (Execution Plan)

### Phase 1: 기반 시스템 구축 (Week 1-2)
*   **GraphQL 쿼리 최적화:** GitHub API Rate Limit을 고려한 쿼리 설계 및 캐싱(Redis) 구현.
*   **PyDriller 파이프라인:** `git-filter-repo`와 연동하여 순수 히스토리 추출 스크립트 작성.

### Phase 2: 분석 엔진 고도화 (Week 3-5)
*   **AST 파서 통합:** `Tree-sitter`를 Python/Node.js 환경에 연동하여 시맨틱 Diff 로직 구현.
*   **AI/Boilerplate 필터:** 커밋 시간차 분석(Vibector) 및 LSH 알고리즘 적용.

### Phase 3: 병렬화 및 LLM 연동 (Week 6-8)
*   **에이전트 오케스트레이션:** 각 분석 모듈을 비동기 워커로 분리하고 결과 취합 로직 구현.
*   **질문 생성 프롬프트 엔지니어링:** 분석된 메트릭(수치)을 LLM 프롬프트에 주입하여 맞춤형 면접지 생성 테스트.

### Phase 4: UI/UX 및 대시보드 (Week 9+)
*   **Jitta 대시보드:** 복잡한 코드를 기술 부채, 숙련도 그래프 등 시각적 지표로 변환하여 CEO에게 제공.

## 6. 결론 및 제언

이 설계는 기존의 단순 텍스트 분석을 넘어, 소스 코드의 **구조적(AST)**, **역사적(Git History)**, **통계적(AI Pattern)** 특성을 모두 고려한 다층적 접근입니다.

*   **정확도:** AST 기반 시맨틱 분석으로 포맷팅 노이즈를 제거하여 보장.
*   **수치화:** Halstead 및 API 깊이 분석을 통해 결정론적인 점수 산출.
*   **속도:** 분석 에이전트의 병렬 처리를 통해 대규모 레포지토리도 신속하게 처리.

이제 **"REST API로 프로토타입을 만들되, 실제 서비스 단계에서는 GraphQL로 전환"**하라는 초기 제언을 넘어, **PyDriller와 Tree-sitter를 결합한 하이브리드 분석 엔진**을 구축하는 것이 프로젝트 '짓다'의 성공을 위한 가장 확실한 기술적 경로입니다.
